# knowledge/ — Course wiki

**Cumulative knowledge base. The agent writes here; you can read, correct or extend it.**

Each `.md` file is an **atomic note** about one concept. The wiki grows session by session: every time the tutor emits a *📌 For your notes* snippet (see `AGENTS.md §2.7`), it also persists it here as a new note or as an update to an existing one.

Concepts that are easier to understand by playing with them also get an **interactive widget** in `interactives/` (see `AGENTS.md §2.2`).

---

## Conventions (mandatory)

### 1. One concept per file
`kebab-case` names, no date, no block number in the name:
- ✅ `binary-search.md`, `big-o-notation.md`, `dijkstra.md`
- ❌ `wk2-arrays.md`, `2026-06-26-bigo.md`

If the same concept appears in two blocks, **a single note** ties them together. The chronology goes in `progress/log.md`, not here.

### 2. YAML frontmatter

Every note starts with (keys always in English; the note's body is written in the session language):

```yaml
---
topic: human-readable name of the concept
block: 1                          # plan block where it was introduced
status: draft | reviewed          # draft    = generated by the agent, not yet reviewed
                                  # reviewed = validated by the user
last_updated: 2026-06-26
related: [other-note, third-note] # no wikilink brackets in YAML
interactive: interactives/binary-search.html   # optional
---
```

### 3. Wikilinks `[[note-name]]`

Link other wiki notes with the syntax `[[file-name-without-extension]]`. Example:
> A `binary search` requires the array to be sorted — see [[sorting-basics]] and [[big-o-notation]] for the cost analysis.

If the target doesn't exist yet, **link it anyway**: it marks a gap to fill in the future.

### 4. Recommended internal structure

```markdown
---
topic: ...
block: ...
status: draft
last_updated: YYYY-MM-DD
related: [...]
---

# {human-readable title}

## Definition
Short, direct sentence.

## Intuition
Everyday analogy, ASCII drawing if applicable.
▶ Interactive: [interactives/<slug>.html](interactives/<slug>.html) — what to try with it.

## Key facts
- Complexity / properties / formulas / whatever applies.

## Where it shows up
Typical contexts (in interviews / exams / production / the core material).

## Minimal example
Snippet or concrete case.

## Common pitfalls
Typical mistakes, distinctions from similar concepts.

## References
- {{MATERIAL_BASE}}: Ch. X, p. Y
- Related notes: [[note-1]], [[note-2]]
```

### 5. Interactives (`interactives/`)

- One self-contained `.html` file per concept, named like its note: `interactives/<note-slug>.html`. Variants: `<note-slug>--<variant>.html`.
- Inline CSS/JS, no build step, opens with a double-click in any browser. External libraries only with an exact pinned version from a CDN.
- A caption at the top with the guided task, controls mapped to the concept's variables, live numeric values, and a **Reset** button.
- Always linked from its note (`interactive:` in the frontmatter + a line in *Intuition*) and listed in the *Interactives* section of the index below.

## What does NOT go here

- **Progress state** (which session, which weaknesses) → `progress/`
- **User work** (code, solutions) → `progress/solutions/`
- **Raw source material** → `materials/`

If you're unsure whether something goes in `knowledge/` or `progress/`, ask yourself: *"will this still be useful in 6 months, even after the course ends?"* — if yes, `knowledge/`. If not, `progress/`.
